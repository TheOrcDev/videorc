# Plan 071: Linux distribution packaging — deb (Ubuntu), AUR binary PKGBUILD (Arch), rpm (Fedora)

> Executor: S1–S6 are code slices on a branch of current `main`. No merge or
> release is authorized by this plan. Read AGENTS.md, `docs/linux-port-plan.md`
> and `docs/linux-dev-loop.md` first. AppImage stays the primary Linux artifact
> and the only self-updating format; deb/rpm installs report honest
> "managed by your package manager" update state (S5). The Linux Alpha lane is
> candidate-only and private; nothing here is public release authorization.

- Status: PLANNED 2026-09-28, then EXECUTING on a `feat/linux-distro-packaging`
  branch. Planned against current `main`.
- Execution status (2026-09-28): S1–S6 implemented (S1 icon/metainfo/desktop;
  S2 deb + validator + unit tests; S3 AUR PKGBUILD/install/.SRCINFO; S4 rpm
  config + structurally validated; S5 updater guard; S6 scripts, workflows,

  (14/14), `appstreamcli validate`, `makepkg --printsrcinfo` sync, YAML/JSON
  parses, `pnpm check:text-files`, shell syntax. Unrun locally (no node_modules /
  no built packages on this box): `pnpm typecheck`, desktop unit tests, a real
  deb/rpm build + `pnpm validate:linux:dist`, and the AppImage payload validator
  (js-yaml-dependent tests fail on import here). CI (ubuntu-24.04) covers those;
  rpm install/launch acceptance stays blocked on the Fedora named box.
- Priority: P1. Effort: M (six slices, mostly packaging config + node scripts +
  one small TS guard + docs).
- Owner decisions (2026-09-28):
  - In-app auto-update is **disabled for deb/rpm installs** (Linux non-AppImage).
    `latest-linux.yml` stays AppImage-only. Distro package managers own updates.
  - **RPM is kept**: config + CI structural validation now; install/launch
    acceptance stays blocked until a named Fedora/RHEL box is recorded.
  - **Arch ships via a checked-in AUR binary PKGBUILD** (`videorc-bin` style),
    not the electron-builder `pacman` target (still beta).
- Context from external research (electron-builder 26.8.1, electron-updater 6.x):
  deb builds on ubuntu-24.04 runners with zero installs (fpm is auto-downloaded);
  rpm needs the `rpm` package (present on the runner); AppStream metainfo is
  never generated by electron-builder and must be authored + shipped.

## Why

The Linux Alpha lane currently produces a single AppImage. Ubuntu, Debian and
Fedora users expect `.deb`/`.rpm` native packages (software-center install,
hicolor icons, desktop entries, AppStream metadata, package-manager updates);
Arch users expect an AUR package. All three keep the product's LGPL-only FFmpeg
policy by bundling the pinned Linux FFmpeg — they never depend on a distro
`ffmpeg` (which could be GPL or carry x264).

## Out of scope

- Flatpak, Snap, and the electron-builder `pacman` target (follow-ups).
- Public Linux promotion (still blocked by the missing release-controller
  finalizer; candidate storage only).
- Installing on the Ubuntu 24.04 box from here (box still owed by L6); the
  release lane builds and structurally validates on `ubuntu-24.04`, and this
  plan documents the named-box acceptance steps.
- Any change to capture/encoding/preview code.

## Ordered slices

### S1 — Foundation: icon, AppStream metainfo, desktop entry (P1, S)

Files:
- `apps/desktop/build-resources/icon.png` — 512×512 PNG derived from
  `icon.icns` (ImageMagick on the executor box, or `sips` on macOS for later
  re-derivation). Needed for hicolor icon generation in deb/rpm and for the AUR
  package icons.
- `packaging/linux/metainfo/dev.theorcdev.videorc.metainfo.xml` — AppStream
  metainfo: id `dev.theorcdev.videorc`, component type `desktop-application`,
  `<launchable type="desktop-id">videorc.desktop</launchable>`, name, summary,
  AGPL-3.0 license, developer name, release entry with the packaged version,
  categories, OARS rating. No screenshots first pass (owner assets pending).
- `apps/desktop/electron-builder.yml` `linux:` section:
  - `desktop.entry` with `Name=Videorc`, `Comment`, `Categories`,
    `StartupWMClass=Videorc` (verify actual WM_CLASS on the box; fall back to
    `executableName`), `Terminal=false`.
  - Top-level `linux.mimeTypes: [video/mp4, video/quicktime, video/x-matroska,
    video/webm]` (recording outputs the app produces; adjust after checking
    actual export formats).
  - `synopsis`, `description`, `category: Video` (kept), `packageCategory`.

Gates: `appstreamcli validate packaging/linux/metainfo/*.xml`;
`desktop-file-validate` on the generated entry (via `--print-deb` dry run or the
AppImage payload on the box); `file`/`identify` on `icon.png` (512×512 PNG);
`electron-builder --linux dir` succeeds with the new config on the box/CI.

### S2 — deb target (Ubuntu/Debian) (P1, S)

Files:
- `apps/desktop/electron-builder.yml` `deb:` config: `afterInstall`/
  `afterRemove` (see scripts), `priority: optional`, `packageCategory: Video`
  via the linux key, `depends` explicit runtime libs matching the release lane
  install list (`libgtk-3-0t64`, `libnss3`, `libasound2t64`,
  `libatk-bridge2.0-0t64`) and `Recommends: pipewire, xdg-desktop-portal`,
  `libva2` and a VAAPI driver + `intel-media-driver`/`mesa-va-drivers`
  (OpenH264 software fallback keeps them recommends, not hard deps).
- `packaging/linux/deb/after-install.sh` — `gtk-update-icon-cache`,
  `update-desktop-database`, and install the metainfo XML from the package
  payload (`/opt/Videorc/resources/…`) into `/usr/share/metainfo/`.
- `packaging/linux/deb/after-remove.sh` — remove the metainfo copy, refresh
  caches.
- `scripts/lib/linux-dist-package.mjs` + `scripts/lib/linux-dist-package.test.mjs`
  — pure helpers: deb/rpm artifact-name contract, structural checks
  (package contains backend + bundled ffmpeg, metainfo, icons, desktop file).
- `scripts/validate-linux-dist-package.mjs` — runs the checks against built
  artifacts (`ar t`/`dpkg-deb -c` when available, else listed file inspection
  via `bsdtar`).

Gates: `node --test scripts/lib/linux-dist-package.test.mjs`; on CI
(ubuntu-24.04): `pnpm package:desktop:linux:deb` succeeds and the validator
passes; `dpkg -c` shows `/usr/share/metainfo`, hicolor icons, and the desktop
file. Named-box acceptance (owed): `dpkg -i` on Ubuntu 24.04, app launches,
`pnpm smoke:packaged` with executable override, portal-capture smoke.

### S3 — AUR binary PKGBUILD (Arch) (P1, S)

Files:
- `packaging/linux/arch/PKGBUILD` — `pkgname=videorc-bin`; `pkgver` from the
  release version; `depends=(gtk3 nss alsa-lib libpipewire xdg-desktop-portal
  libva mesa)` with `optdepends` for VAAPI drivers and OpenH264 note; downloads
  the AppImage from the candidate/release storage URL with the exact sha256 from
  the `.sha256` sidecar, verifies it, installs to `/opt/videorc` via
  `--appimage-extract` (bsdtar) or by mounting, plus hicolor icons,
  `videorc.desktop`, and the metainfo XML.
- `packaging/linux/arch/videorc.install` — `post_install` runs
  `gtk-update-icon-cache` + `update-desktop-database`; `pre_remove` removes
  nothing extra (package owns files); `post_remove` refreshes caches.
- `packaging/linux/arch/.SRCINFO` — generated (`makepkg --printsrcinfo`),
  committed for AUR submission.

Gates on the Arch/executor box: `makepkg --printsrcinfo` matches `.SRCINFO`;
`makepkg --verifysource` (when the source URL is reachable) verifies the sha256;
`makepkg -f` builds the package; `namcap` clean or accepted warnings. Named-box
acceptance (ogre, Arch family): `makepkg -si`, `videorc` launches, portal
capture smoke, honest update state.

### S5 — Honest updater state for native installs (P1, XS)

Files:
- `apps/desktop/src/main/updater.ts` — in `initAutoUpdater` (and the manual
  `updates:check` path), when `process.platform === 'linux'` and
  `!process.env.APPIMAGE`, report `{ type: 'unsupported', reason:
  'linux-native-install' }` and do not attach the updater listeners, so a deb/rpm
  install never probes a feed it cannot consume.
- `apps/desktop/src/main/updater-status.ts` — map the new reason to the existing
  `unsupported` state with an honest message ("Updates are managed by your
  package manager on this install.").
- Renderer copy (Settings → About & updates) if the reason already flows.

Gates: `pnpm --filter @videorc/desktop typecheck`; desktop unit tests
(`pnpm --filter @videorc/desktop test`); `pnpm smoke:record-latency:gate`
regression (S5 touches `updater-status`, not capture, but the status flows
through Settings), and `pnpm smoke:packaged` behavior on a .deb-installed app
(named box).
