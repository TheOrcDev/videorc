# S19 show marker contract

Source checkpoint only. Runtime, app, device, provider, migration and media alignment acceptance remain **not-run**. Markers do not activate recording, replay, extraction or a provider.

- Target is `native-take {sessionId}` or `cloud-show {showId}`. A cloud receipt never has a fabricated native session/file. Native marker/Clips workflows retain their existing contracts.
- Owner-authenticated `GET/POST/DELETE /api/cloud/shows/:id/markers` uses the existing account session. POST accepts canonical UUID `operationId`, `kind: marker|clip`, optional bounded label, clip `lookbackSeconds:30|60`, and source `manual|voice|remote|agent`. Author comes from session, never request. Owner show lookup precedes journal access. GET `?id=` returns found/absent/deleted; deleted does not return private payload.
- Show clock is **server acceptance minus persisted show.createdAt**. `time.basis=server-show-created-at`, `observation=server-accepted`. This is not click time, provider PTS, audio capture time, UTC-to-media evidence or a native anchor. `sourcePosition` is separate voice metadata with `uncertaintyMs:null`. S15 source-to-show uncertainty stays null.
- `target.liveIntervalId` only names S16's confirmed overlapping live interval; record-only has null. `takeIds` and `providerEgressIds` remain separate S20 associations, even if a recorder stays on across End/Go Live. An association is **not an extractable media range**. Production receipts explicitly return `media.extractable:false`, reason no-recording or clock-unconfirmed.
- `mapMarkToSegments` requires measured evidence matching show, show origin, take, generation, explicit finite uncertainty and contiguous segment coverage. No production evidence supplier is qualified/provided by S19; the function cannot be used to infer evidence from a take's wall-clock start. Native monotonic origin/incarnation from published S13a is not consumed or copied.
- Durable per-show PostgreSQL journal: bounded 2000 entries including deletion tombstones; optimistic revision CAS, eight retries; repeat ID+same canonical request returns original receipt before lifecycle checks. Changed request conflicts; tombstone refuses resurrection. No historical timestamps rewritten; expiry refuses new marks; saved metadata and retry receipts remain readable while the account-owned show row exists. DELETE is idempotent. Additive migration 0043_cloud_show_marks.sql; no database migration executed.
- Desktop RPCs: cloud.marker.create/get/delete, cloud.markers.list, cloud.marker.voice.configure. Event cloud.marker.created carries receipt; cloud.marker.voice.status carries showId and listening. Comments relay actions cloudCreate/cloudGet/cloudDelete. Native session.marker RPCs stay native. clip.mark resolves the active owner; cloud request may carry operationId or bounded requestId. Remote intentId survives into requestId. Agents may retain operationId to retry; outputs expose only markerId/showId/atSeconds/mediaAvailable plus clip facts, not account/source transcript data.
- Host voice uses S15 immutable processed source owner plus admitted marker consent epoch. It never consumes guest audio; queued writes cancel on source/mute/consent loss. Captions remaining enabled does not retain voice-marker consent. Clip phrases preserve bounded cross-final tail/dedupe. No new STT or model path.
