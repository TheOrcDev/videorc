with `complete: true`. The JSON beside this note
(`2026-11-23-linux-l1.5-ogre.json`) is the script's output, unedited. No media
is committed.

## `auto` with nothing set

The direct matrix command with `VIDEORC_LINUX_H264_ENCODER` unset (and no
device or libva pins) chose `hardware-vaapi` on `renderD128` with the
standard profile, listed `renderD129` as quarantined, and passed: 1080p30,
level 4.0, BT.709/tv, 30.0 fps, bridge input 29.9 fps, stop tail 20 ms.

In the dev app with the same environment (release backend, real FaceTime HD
camera, camera-only scene), the backend logged "VAAPI H.264 encoder selected
after probing /dev/dri/renderD128". The Output page's Clips row read "The
newest seconds are on disk, ready to save, and deleted as they age." with the
switch on; the OpenH264 refusal ("Off on this computer …") did not appear.
Health showed the ring's encoder at 0.86× and "Uneven frames" for
rendering, from the CPU compositor at 1080p30 (plan 257's compositor row,
D6), not from the encoder.
