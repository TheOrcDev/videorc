## Confirmed bug and fix

The docked Preview remembers the number of the last startup step that
stalled. After that step changes, returning to it immediately revives the
old warning instead of allowing another 20 seconds. This can happen when
the capture engine reconnects or a source returns to starting before the
first frame arrives.

The mounted React regression reproduces it for all three steps: wait for
the warning, change steps, then return. Before the fix, all three cases
failed (`stalled` instead of `starting`). Timer cancellation and unmount
cleanup already passed. The fix resets the warning state on a step change;
ordinary status renders retain the current deadline.
