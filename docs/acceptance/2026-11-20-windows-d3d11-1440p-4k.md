# 2026-11-20 Windows D3D11 recording at 1440p and 4K30 (#173)

## What changed

The D3D11 session selector refused every output past 1920x1080
(`windows-d3d11-media-primary-output-unqualified`, since #202), so 1440p30/60,
4K30 and the 1440p/4K portrait twins recorded through the CPU compositor and
uploaded system-memory NV12 to Media Foundation. The selector now takes every
output inside H.264 level 5.1 (at most 36,864 macroblocks a frame, 983,040 a
second, no side past 4096). 4K60 needs level 5.2 and stays on the legacy
bridge with the same named reason; an encoder that refuses a size still fails
the pump's startup into the named `windows-d3d11-media-startup-failed`
fallback.

The encoded-bridge smoke now requires direct D3D11 recording for the portrait
profiles too: on main, vertical 1080p already ran on D3D11, and the smoke's
portrait exemption failed it for not using the CPU compositor.

## Host

`win11-x64-i5-8400-gtx1650-super`: Intel Core i5-8400, NVIDIA GeForce GTX 1650
SUPER (driver 32.0.16.1742), Windows 11 Home 10.0.26300, 1920x1080 primary
display (1440p and 4K outputs scale the 1080p capture up on the GPU). Packaged
`apps/desktop/release/win-unpacked` from main `c2129141`; branch and base
differ only in `videorc-backend.exe`.

runs a load test as well as the CPU/RSS comparison. Main's runs were measured
with the artifact cadence tolerance widened locally (not committed) so they
would write a report; their cadence failures are listed as measured.

An earlier main run of the same 4K30 take failed outright at 27.52 fps
(8.3% short). FFmpeg (the MPEG-TS/MP4 writer) stays at 1-2% average on both;
Electron roles do not change. CPU percentages are of one core.

The 1080p60 control (D3D11 on both) measured 58.05 fps on main and 59.46 on
the branch under telemetry, and 59.41 on main without it: that difference is
run-to-run variance on this host, not this change.

## Clips hand-over at 1440p

The Clips ring is a replay-only session through the same selector, so a
remembered 1440p or 4K profile now arms it on D3D11 and Record takes over its
media thread (#1330). `pnpm smoke:record-latency -- --real-screen --profile
tutorial-1440p30 --cycles 3` (dev app, branch release backend, Clips on):
3/3 cycles on the D3D11 media path, 0 on the CPU compositor, every artifact
2560x1440 and through the analyzer. Warm click to recording p95 1,508 ms
against 1,433 ms for the same run at 1080p30; both miss the 800 ms
report-only budget by the same margin because the dev app opens the
microphone through FFmpeg DirectShow (no `ffmpeg-capture.exe` in vendor).

- Livestream, split record/stream, Clips, captions/highlights and the second

  change those paths; they remain open on #173.
