# Videorc 0.9.147 release

Status (2026-10-23): macOS `0.9.147-beta.1`, Windows `0.9.147-alpha.1` and
Linux `0.9.147-alpha.1` are **published** (Windows and Linux owner-waived).

The owner said in-session: "ok let's now release all three platforms, you have
my approval to auto approve and auto waive everything".

## Source

- Bump and changelog: #747, squash `f8a5c2209a71722fd2b51cc85383aafb0411c537`.
  macOS and Linux build from this commit.
- Windows builds from #748, squash
  `9d45c43cb67b6fdf2971afac855953f251c9e5df`. It changes four test files only
  (two desktop tests, two Rust test modules), so the shipped app code is the
  same on all three platforms.
- The first Windows candidate, run
  https://github.com/TheOrcDev/videorc/actions/runs/39944753211 from
  `f8a5c220`, failed "Run source and unit gates" before signing. Two desktop
  tests compared joined paths with `/` literals: `managed-asset-roots.test.ts`
  (#744) and `sound-files.test.ts` (#743). Three Clips Rust tests had the same
  assumption and would have failed next: `replay_buffer.rs` concat list and
  segment muxer args, and `recording.rs` replay ring args. #748 fixed all five.
  Nothing was signed, stored, approved or waived, so the same release ID
  `0.9.147-alpha.1` was dispatched again from `9d45c43c`, as for 0.9.142.
- `main` CI:
  - `f8a5c220`: Linux passed. CI and Windows were cancelled when #748
    superseded them.
  - `9d45c43c`: JS, Linux gates and the Windows installer artifact passed.
    Rust and the Windows release source gates were cancelled when the waiver
    commit superseded them. "Windows startup incident diagnostics" failed, as
    on every PR since early October.
  - The Windows candidate's own source and unit gates passed on `9d45c43c`,
    including the full Rust suite.
- Owner waivers for both Alphas: #749
  `412b6f79e841a433849131bae7c2fde1822e1943`.

## Known gaps

- No macOS clean-machine or device acceptance pass was recorded, as for the
  recent Betas.
- Soundboard (#743): on Linux the "Hear sounds yourself" monitor is silent,
  because the `sound` asset host still resolves Electron's userData while the
  backend keeps its folders beside `~/.videorc` (#744 fixed this for takeovers
  and banners only). The Alpha entry lists it as a known issue; sounds still
  reach recordings and streams. Seven CodeRabbit findings on #743 are open
  for a follow-up. The owner's by-ear check of the starter sounds and a live
  take with a pad are owed, as are Windows and Linux on-device runs.
- Clips (#694) merged after a 17-file conflict merge with main, and its smokes
  were not rerun afterwards. Windows, Linux and real-game checks are owed.
- Alpha changelog entries are not public (`/releases/0.9.147-alpha.1`
  answers 404), and no Alpha Discord post was sent, as for every Alpha since
  `0.9.91-alpha.1`.
- The Linux manifest's known-issues URL, `/linux-alpha`, answers 404, as it did
  for 0.9.144 and 0.9.146.
- The signed-in download pages were not checked by eye.
