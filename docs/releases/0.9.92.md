# Videorc 0.9.92 Beta 1 (macOS)

Multistreaming is free for every plan. The Premium gate on destination count
is removed end to end and every tier gets the same cap of five destinations.
Streaming quality tiering (Basic 1080p30, Premium 1080p60 / 4K30), cloud AI,
live captions and co-host gates are unchanged.

## Scope

- #338: backend `STREAMING_MAX_DESTINATIONS = 5` for basic/premium/developer;
  Basic emits the `multistreaming` capability as enabled (feature id and
  `max_destinations` stay on the wire, values only). `validate_session_entitlements`
  drops the Premium requirement; the over-cap error is neutral and never
  contains "Premium" (the renderer regex-sniffs that word into an upgrade
  toast). Renderer: Premium lock chip and "View Premium" strip removed from
  destination rows, always-rendered Switch with a muted limit strip. Smoke
  `smoke-multistream-app.mjs` cap 4 → 5. `docs/distribution.md` boundary table
  updated; dated addendum on plan 016.
- #339: version bump to 0.9.92.
- Web (videorc-web #16, merged after this release went live): policy
  `STREAMING_MAX_DESTINATIONS = 5` for both tiers, `BASIC_LIMITS.multistreamingEnabled`
  true; pricing table, landing Premium section, `/premium`, `/account`, terms,
  metadata, JSON-LD and the Windows alpha contract doc rewritten so nothing
  ties multistreaming or destination count to Premium. The false "relays to
  five platforms on real infrastructure" claim on `/premium` is gone.
- Plan: `~/Documents/Obsidian Vault/plans/partial/2026-09-15 - Videorc Multistream Goes Free Plan.md`.

## Why

Multistreaming never had a server bill: the backend builds one FFmpeg `tee`
with one RTMP leg per target and pushes from the user's machine. The 0.9.5
gate was a value-based paywall. The survey also found the site had promised
Premium five destinations since 0.9.5 while the app hardcoded three; the
desktop reads only the tier from `/api/ai/capabilities` and never consumed the
server's limits. One shared constant per side closes that drift.
