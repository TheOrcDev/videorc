# Videorc 0.9.146 release

Status (2026-10-22): macOS `0.9.146-beta.1`, Windows `0.9.146-alpha.1` and
Linux `0.9.146-alpha.1` are **published** (Windows and Linux owner-waived).
This record also covers 0.9.145, which shipped on macOS only.

The owner said in-session: "release on all three platforms, you have my
approval to auto approve and auto waive".

## 0.9.145 (macOS only)

- Bump and changelog: #734, squash `a53d88372841e28afaab8ffc1ffd8847f335cb70`
  (scope #632 separate source recordings, #619 stats bar without stream
  health). Released by another Claude session, which handed the rest over.
- macOS `0.9.145-beta.1` is **published**: DMG SHA-256
  `4d30055767b550494559bed6cfa2c2aa891ce06a68c98095d3be93de4c84cf8d`,
  187,211,870 bytes; update zip 165,959,277 bytes. Uploaded to Neon (primary)
  and Hetzner (mirror), feed and zip verified, Discord sent.
- `0.9.145-alpha.1` was **abandoned unpublished**. Its Windows candidate (run 39755956045) and Linux candidate (run 39755961219) hung in their unit gates
  and were cancelled. Since #632 merged, three backend tests had hung on every
  host without Metal, and #737 fixes that. Nothing was signed, stored,
  approved, waived or published. A fixed source needs a new numeric version, so
  #738 removed the `0.9.145-alpha.1` changelog entry, which was never public.

## Known gaps

- No macOS clean-machine or device acceptance pass was recorded, as for the
  recent Betas.
- #632 (separate source recordings) merged on the owner's call before the plan
  158 quiet-host runtime acceptance and a packaged-app camera take. It ships in
  macOS 0.9.145 and 0.9.146. On Windows and Linux the switch is visible but
  refuses to record, which the Alpha entry lists as a known issue.
- #736 (Discord go-live posts) merged before its CI finished. The owner's
  private-server webhook check is still owed.
- Alpha changelog entries are not public, and no Alpha Discord post was sent,
  as for every Alpha since `0.9.91-alpha.1`.
- The Linux manifest's known-issues URL, `/linux-alpha`, answers 404, as it did
  for 0.9.144.
- The signed-in download pages were not checked by eye.
- The Windows candidate workflow does not run the dead-renderer smoke, so the
  shipped installer's own build never ran it; the rerun on `main` passed it
  from the same source.
