# Videorc 0.9.95 Beta 1 (macOS)

Live Co-host tick wire contract v2 ships on the desktop. The app sends the
streamer's chat rules and understands richer flags, highlight suggestions,
chat alerts and mood scores, with forward tolerance for anything the server
adds later. Executes the desktop half of the vault plan "2026-09-18 - Videorc
Co-host Jev Moderation Plan".

## Scope

- #356: co-host wire v2 (`promptVersion: 2` + `rules`, silent fallback to v1
  on `prompt-version-unsupported`), `#[serde(other)] Unknown` on every co-host
  wire enum, item-by-item deserialization of flags/highlights/alerts,
  `CohostSettings.rules` (10 x 120 chars) with a "Chat rules" editor, richer
  flag chip, "Suggested" badge through the existing `toggleCommentHighlight`
  path, alert chip in the co-host pane, renderer-only "Flag sensitivity"
  filter over `confidence`.
- Server half is videorc-web #20 (merged `802ef937`): optional TypeSafe Jev
  evaluation-model judge, **off by default**.
- #357: version bump to 0.9.95 + changelog entry.

## Known product gap shipped on purpose

Production has no `VIDEORC_AI_COHOST_JUDGE_ENGINE` set, so the server runs the
`llm` engine. That engine accepts `rules` but ignores them and returns no
`confidence`, highlights or alerts. The "Chat rules" editor and the "Flag
sensitivity" control therefore have no effect for users until the judge is
switched on. Owner decision 2026-09-20: ship them anyway. The changelog says
rules start working "as the new moderation rolls out".
