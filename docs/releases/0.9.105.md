## Owner decisions (2026-09-24)

- **"Release again after merge,"** right after #405 merged. macOS follows the
  regular Beta scope of 0.9.93 to 0.9.104: build, sign, notarize, staple and
  run the maintained artifact validation, then publish without the
  real-device, endurance (60/15-minute), clean-machine and strict provider
  gates. Those gates are recorded below as not run; no PASS is claimed for
  them.
- **Neon is the only release origin** (owner, 2026-09-23).
- **Windows** builds the `0.9.105-alpha.1` candidate from protected main after
  macOS is live. The owner approves the protected sign job in GitHub, and
  nothing may merge to protected main while it waits: the job refuses a moved
  main. Public promotion waits for the release owner to commit
  `docs/acceptance/windows-alpha/0.9.105-alpha.1.json`, either a PASS record or
  an owner waiver (first public Alpha).

## Scope and source

Since macOS 0.9.104 (`296ee36930f60b8dc9ff7c9252945c7c49c5979a`), protected
main gained:

- **#405, a hairline between the Stream Manager's stats strip and its panes**
  at Wide and Medium, which the owner spotted in 0.9.104.
  `probe:comments-window` now checks the rule at every sweep width. It failed
  at 640, 800, 1040 and 1280 px without the fix.
- **#404, the 0.9.104 release record.** Docs only.

`0.9.104-alpha.1` was dropped before signing (see
[the 0.9.104 record](0.9.104.md)), so its unpublished changelog entry moves
forward as `0.9.105-alpha.1`.

Mac source commit: `c2038a0b7187e659bad075afe28f9648deb8dd95`. Windows
candidate source commit: the same.
