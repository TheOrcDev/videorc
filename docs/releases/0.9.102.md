## Owner decisions (2026-09-23)

- **Neon is the only release origin.** "Just neon, we are not using hetzner
  anymore." The upload loaded only the Neon credentials and cleared every
  Hetzner and R2 variable; Hetzner received nothing for this release. The
  Hetzner keys are still present in the local release env and in the
  `windows-alpha-release` GitHub environment, and the runbook still describes
  Hetzner as a mirror; both need follow-up before the next Windows promotion.

- **"Merge and release."** The owner asked to merge #395 and release. macOS
  follows the regular Beta scope of 0.9.93 to 0.9.101: build, sign, notarize,
  staple and run the maintained artifact validation, then publish without the
  real-device, endurance (60/15-minute), clean-machine and strict provider
  gates. Those gates are recorded below as not run; no PASS is claimed for them.
- **Windows follows the 0.9.101 route.** After macOS is live, build and sign the
  `0.9.102-alpha.1` candidate from current protected main. Public promotion
  waits for the release owner to commit
  `docs/acceptance/windows-alpha/0.9.102-alpha.1.json`, either a PASS record
  from a physical acceptance run or an owner waiver (first public Alpha). The
  release agent does not author it.

## Windows candidate

[Run 35908960780](https://github.com/TheOrcDev/videorc/actions/runs/35908960780)
built `0.9.102-alpha.1` from `fdf6ce68743bf641a7db54619644d942dbbd7716` (the
macOS source). The unsigned job passed. The protected sign job was approved and
signed the payload, then its "Validate exact signed release bundle after logout"
step failed: `windows-release-artifact: FAIL (Capture executable hash does not
match its manifest.)`.

Cause: #389 added the capture worker `ffmpeg-capture.exe` with a
`capture/MANIFEST.json` that pins the executable's build-time SHA-256. The sign
job Authenticode-signs every packaged executable, which rewrites that file, so
the signed bundle can never match the pin. This was the first candidate signed
since #389 (the 0.9.100 and 0.9.101 candidates never reached signing). Nothing
was stored or published. The fix ships in the 0.9.103 prep: signed-bundle
validation proves the worker by its signature, like `Videorc.exe`.
