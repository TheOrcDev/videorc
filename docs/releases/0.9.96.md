# Videorc 0.9.96 Beta 1 (macOS)

X comments reach the Comments window. X shut off the legacy Periscope chat
WebSocket (every X session logged `x-live-chat-failed` after 8 attempts and no
X comment was ever stored), and now delivers broadcast chat only through the X
Activity API `broadcast.chat` event, pushed to a signed public webhook. The
desktop binds to a videorc.com relay and long-polls it. Executes the vault plan
"2026-09-19 - Videorc X Comments via XAA Plan".

## Scope

- #360: `x_chat.rs` rewritten (OAuth Echo bind, one `broadcast.chat`
  subscription per broadcaster, long-poll), subscription helpers in
  `x_live.rs`, cleanup on X disconnect, `pbs.twimg.com` avatar allowlist. The
  connector no longer gives up mid-session; only a missing Videorc sign-in or a
  rejected X authorization is terminal.
- Server half is videorc-web #21 (merged `78e0c48a`): webhook with CRC and
  signature checks, 24 h transit table, bind and long-poll routes, daily
  maintenance cron.
- #361: version bump to 0.9.96, changelog entry, removal of the held
  `0.9.95-alpha.1` entry.

## Known gap at ship time

Web migration `0014_add_x_chat_relay.sql` was **not applied** when this build
went live. Vercel marks `DATABASE_URL` sensitive (the CLI returns it empty) and
the agent is barred from `videorcweb/.env`, so only the owner can apply it.
Until then the relay bind fails with 5xx and the app shows X chat as
"Reconnecting"; it heals by itself once the tables exist. The Discord
announcement is held for the same reason.

stored on 2026-09-19 22:19Z from `a33e4463d5960a68f9f09aacbc7d703638e8a841`

`a23d76e35c79a1148bc737bc7129cf9aec46cb912dede119c418d306309f9229`) and stopped
at physical acceptance. Its changelog entry (#358) would have been published by
this macOS upload, so #361 removed it and bumped the version, which is the
runbook's procedure for abandoning an unpromoted candidate. The release agent
recommended that option to the owner while wrongly stating the candidate had
never been dispatched (stale session memory; the workflow history was not

preserved. Windows rolls forward as `0.9.96-alpha.1`, still behind the
0.9.91-alpha.1 pilot's missing acceptance record. Once that entry is on
`main`, hold macOS uploads again.
