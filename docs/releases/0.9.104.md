# Videorc 0.9.104 release

Status: preparing macOS arm64 `0.9.104-beta.1` and Windows 11 x64
`0.9.104-alpha.1` from protected main plus this prep update. Neither artifact
has been signed or published.

## Owner decisions (2026-09-24)

- **"Make a release,"** right after #402 merged. macOS follows the regular Beta
  scope of 0.9.93 to 0.9.103: build, sign, notarize, staple and run the
  maintained artifact validation, then publish without the real-device,
  endurance (60/15-minute), clean-machine and strict provider gates. Those gates
  are recorded below as not run; no PASS is claimed for them.
- **Neon is the only release origin** (owner, 2026-09-23).
- **Windows** builds the `0.9.104-alpha.1` candidate from protected main after
  macOS is live. The owner approves the protected sign job in GitHub, and
  nothing may merge to protected main while it waits: the job refuses a stale
  main, which is how `0.9.101-alpha.1` and `0.9.103-alpha.1` were lost. Public
  promotion waits for the release owner to commit
  `docs/acceptance/windows-alpha/0.9.104-alpha.1.json`, either a PASS record or
  an owner waiver (first public Alpha).

## Scope and source

Since macOS 0.9.103 (`a3ababf9460ce0a9c428d63a568eac7c92e41601`), protected
main gained:

- **#402, the Stream Manager (plan 055) and the X viewer count (plan 054).**
  The Chat window becomes a live dashboard: a stats strip (viewers, followers,
  supporters, tips, chat pace, stream health), an Activity feed, a richer chat
  and Orcle's own pane, laid out by container query from 320 px up. In the
  backend: one viewer total per session, structured event details, an audience
  poller, mid-stream token renewal, opt-in Twitch scopes, and an X viewer parser
  that reads the documented `data` envelope. Evidence:
  [the Stream Manager acceptance record](../acceptance/2026-09-24-stream-manager.md).
- **#400 and #401, Linux fixes (plans 052 and 053).** Linux-only apart from two
  shared changes. The owned-process registry now re-stamps the backend's
  identity when the backend reports ready. Windows software H.264 recordings
  now carry BT.709 colour tags, through the same `h264_metadata` rewrite the
  Media Foundation copy path already used. macOS encoder arguments are
  unchanged.

`0.9.103-alpha.1` never signed (see [the 0.9.103 record](0.9.103.md)), so its
unpublished changelog entry moves forward as `0.9.104-alpha.1`, with the Stream
Manager added.

Mac source commit: pending merge of this prep update. Windows candidate source
commit: recorded after macOS publication.
