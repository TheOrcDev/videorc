# Videorc 0.9.103 release

Status: preparing macOS arm64 `0.9.103-beta.1` and Windows 11 x64
`0.9.103-alpha.1` from protected main plus this prep update. Neither artifact
has been signed or published.

## Owner decisions (2026-09-24)

- **"Make a release."** macOS follows the regular Beta scope of 0.9.93 to
  0.9.102: build, sign, notarize, staple and run the maintained artifact
  validation, then publish without the real-device, endurance (60/15-minute),
  clean-machine and strict provider gates. Those gates are recorded below as not
  run; no PASS is claimed for them.
- **Neon is the only release origin** (owner, 2026-09-23).
- **Windows** builds the `0.9.103-alpha.1` candidate from protected main after
  macOS is live. The owner approves the protected sign job in GitHub: the
  auto-mode classifier treats a release agent approving its own dispatch as
  self-approval. Public promotion waits for the release owner to commit
  `docs/acceptance/windows-alpha/0.9.103-alpha.1.json`, either a PASS record or
  an owner waiver (first public Alpha).

## Scope and source

Since macOS 0.9.102 (`fdf6ce68743bf641a7db54619644d942dbbd7716`), protected
main gained:

- **#394, X scheduled broadcasts (plan 049).** X is the second provider of the
  Upcoming scheduler: schedule, edit, thumbnail, cancel, and Go Live through the
  saved broadcast's own ingest source.
- **#397, the app icon in About**, and in the Windows title row.
- **#398, X scheduling on the new design.** YouTube and X get separate Upcoming
  sections and forms. It also fixes the release-build break #394 introduced
  (`cargo build --release` failed on `X_SMOKE_ACCOUNT_ID`) and the Go Live
  preflight fixture gap that kept `smoke:scheduled-streams` from taking a saved
  X broadcast live; that smoke now passes for YouTube and X.

This prep also fixes the Windows signing blocker recorded in
[the 0.9.102 record](0.9.102.md): signed-bundle validation proves the
`ffmpeg-capture.exe` worker by its Authenticode signature (valid, exact
publisher, timestamped) instead of the pre-signing hash that signing always
changes. The unsigned bytes are still proven before signing.

`0.9.102-alpha.1` produced no stored candidate, so its unpublished changelog
entry moves forward as `0.9.103-alpha.1`.

Mac source commit: pending merge of this prep update. Windows candidate source
commit: recorded after macOS publication.

- X scheduling has never run against a real X account: plan 049's S0 spike
  (create and delete one private schedule) and one real scheduled Go Live are
  still open. Only the fixture path is proven.
- Still pending from plan 050: the owner's by-eye checkpoints, Reduce
  Transparency and Increase Contrast in System Settings, a Windows 11 box pass
  (Mica, and now the title-row icon), and a `probe:preview-lifecycle` re-run on
  an idle machine.
- Not run for this release, per the owner decision above: the real-device
  recording-studio bundle, the 60/15-minute endurance sentinels, clean-machine
  installed acceptance, and strict provider readiness.
