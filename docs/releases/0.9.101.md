## Required validation and known gaps

The scheduled-events implementation passed its local fixture, recording and RTMP
artifact smoke, typecheck, lint, build, desktop and Rust tests in #386. Real
YouTube channel create/edit/thumbnail/live/stop/cancel acceptance was not run
because the provider approval gate remains paused. This is not claimed as a
release-candidate PASS. The prior packaged macOS native-preview probe measured
24.2fps against its 30fps threshold; the new signed candidate must be retested.

The public Windows updater returns HTTP 404 because Windows has never been
publicly promoted, not because a pointer was lost. All 13
`promote-windows-alpha.yml` runs (2026-08-12 → 2026-09-21) used
`RELEASE_STAGE: pilot`. No acceptance record has ever been committed, so the
promotion guard's first-release path applies, and the older Windows changelog
entries came from macOS uploads publishing held entries. Public promotion of
`0.9.101-alpha.1` is therefore the first public Alpha
(`releaseSequence.kind: first-public-alpha`). See
[Plan 048](../../plans/048-windows-auto-update.md). Protected
Windows signing needs TheOrcDev's environment review. Public Windows promotion
requires exact-candidate physical and pilot acceptance or an owner-written,
owner-committed waiver, followed by production verification. No waiver is
prepared by the release agent.

Next action: validate the release branch, merge via reviewed PR, freeze the exact
macOS source, then build and test the signed candidate. Publish each platform
only after its required gate evidence or an explicit owner-directed exception.
No rollback has been performed and no secrets or private evidence are recorded
here.
