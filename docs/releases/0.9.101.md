# Videorc 0.9.101 release

Status: preparing macOS arm64 `0.9.101-beta.1` and Windows 11 x64
`0.9.101-alpha.1`. Neither artifact has been signed or published. Both are
planned from the current protected-main source after this release PR merges.

## Scope and source

The source starts from protected main `921903643ee43368058ffb93ec7d6328dcb224a0`,
which includes the Upcoming workspace and scheduled YouTube event flow (#386).
Public account connection remains paused until Google approval, so the event
flow is limited to authorized verification builds. Windows also carries
the 0.9.100 improvements that were never publicly released on that track.
The old `0.9.100-alpha.1` unsigned candidate run
[35771524986](https://github.com/TheOrcDev/videorc/actions/runs/35771524986)
passed its build checks but was cancelled before protected signing when this new
release was requested. It produced no signed installer or public release. Its
unpublished Alpha changelog entry was replaced with `0.9.101-alpha.1`; published
macOS 0.9.100 bytes and pointers remain untouched. The
[0.9.100 record](0.9.100.md) documents that macOS publication.

Mac source commit: pending merge. Windows candidate source commit: pending merge.
Signed artifact identities, workflow URLs, acceptance records and announcement
results are pending.

## Required validation and known gaps

The scheduled-events implementation passed its local fixture, recording and RTMP
artifact smoke, typecheck, lint, build, desktop and Rust tests in #386. Real
YouTube channel create/edit/thumbnail/live/stop/cancel acceptance was not run
because the provider approval gate remains paused. This is not claimed as a
release-candidate PASS. The prior packaged macOS native-preview probe measured
24.2fps against its 30fps threshold; the new signed candidate must be retested.

The public Windows updater currently returns HTTP 404 even though older Alpha
entries exist. The missing stable pointer needs investigation before any public
promotion; it cannot be treated as first-release bootstrap evidence. Protected
Windows signing needs TheOrcDev's environment review. Public Windows promotion
requires exact-candidate physical and pilot acceptance or an owner-written,
owner-committed waiver, followed by production verification. No waiver is
prepared by the release agent.

Next action: validate the release branch, merge via reviewed PR, freeze the exact
macOS source, then build and test the signed candidate. Publish each platform
only after its required gate evidence or an explicit owner-directed exception.
No rollback has been performed and no secrets or private evidence are recorded
here.
